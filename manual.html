二、口令

当前口令是 2580。

改法：打开 assets/shop-config.js，找到这一段，改引号里的数字：

admin: {
  pin: '2580'
}
这个口令不是安全措施，别指望它防人。
它在公开的 JS 文件里，谁都能看到；而且现在的数据都存各自设备的浏览器里， 别人就算"破解"了，动的也只是他自己的浏览器，碰不到你的数据。 它的实际作用是——防止顾客在你的平板上误点进后台。

以后接了云端，身份由服务端校验，那时候口令才会变成真的门禁。

三、接一单的完整流程

顾客那边

  1. 打开 点单，点 + 加东西
  2. 点底部「去结算」
  3. 选「到店自取」或「堂食」，堂食要填桌号，可写备注
  4. 点「提交订单」，拿到订单号和取餐码
  5. 页面显示微信/支付宝二维码，扫码后手动输入金额转账
  6. 回来把付款单号（账单里的「交易单号」）填进去，点「我已经付好了」
  7. 订单变成「待确认」，等你核对

你这边

  1. 打开 我的订单，切到「店家」
  2. 「待确认收款」里有一单，能看到顾客填的单号
  3. 去微信/支付宝对一下账，确实收到了，点 「确认收款，开始做」
  4. 订单进「待接单」→ 点「接单」→ 制作中
  5. 做好了点「做好了」→ 待取餐。顾客那边取餐码会放大显示
  6. 顾客取走，点「已取餐」→ 完成
如果顾客付了但你没收到，点「没收到，取消」，库存会自动退回。

「今日营收」只算你已经确认收款的单，待确认的不算，不会虚高。

四、改菜单

在 菜单管理 里，输口令进入。当前 13 道菜、4 个分类。

加一道新菜

  1. 点右上「新增菜品」
  2. 填名称、选分类、写一句话介绍
  3. 填价格（单位是元，可以写 22 或 22.5）和库存
  4. 角标选填，比如「招牌」「新品」，会显示在菜名旁边
  5. 图标：点下面的 emoji 快捷选，或直接粘贴任意 emoji
  6. 「立即上架」勾着就能马上被顾客点到
  7. 点「保存」

改价格 / 改库存 / 上下架

  • 改价：点那一行的「编辑」，改价格，保存
  • 改库存：直接点列表里的库存数字，改成新数字，回车
  • 下架：点「下架」，顾客端立刻看不到，数据还留着
  • 调顺序：↑ ↓，调的是顾客看到的顺序
  • 删除：点「删除」，按钮会变成「确认删除？」，再点一次才真删

分类

  • 页面最下面的「分类」可以加新分类，比如「季节限定」
  • 分类名旁边的「改名」「↑」「↓」调整显示
  • 分类下还有菜时不许删，会告诉你有几道
  • 分类顺序 = 顾客点单页上从上到下的顺序
改动只存在你操作的这台设备上。 你在平板上把价格改成 30，顾客用自己手机打开看到的还是原来的 28。 因为现在没有后端，数据存在浏览器里。要让所有人看到同一个菜单，得接云端。

五、开通会员

会员是年费 100 元 / 365 天，不是储值，不能抵扣消费。

顾客申请

  1. 打开 会员，填手机号和称呼
  2. 选微信或支付宝，扫码付 100 元（金额要手动输）
  3. 把付款单号填进去，提交

你确认

  1. 打开 我的订单 → 「店家」
  2. 往下拉，看到「会员开通申请」，有手机号和单号
  3. 核对到账后点「已到账，开通会员」
  4. 顾客刷新会员页，就能看到会员卡和到期日

会员权益的文案在 assets/shop-config.js 的 member.perks 里，改完页面自动跟着变。

六、配置项

需要改的东西几乎都在 assets/shop-config.js 这一个文件里。改完发布、刷新页面就生效。

字段类型说明
backend 字符串 'local' 单机模式（现在）。'cloudbase' 云端模式（还没做）
envId 字符串 云开发环境 ID，切云端时才需要
shop.name 字符串 店名，显示在点单页顶部
shop.slogan 字符串 一句话，留空不显示
shop.openTime 字符串 营业时间
shop.address 字符串 门店地址，留空不显示
shop.notice 字符串 提示条，比如「现点现做，出餐约 15 分钟」
pay.methods[] 数组 收款方式。每项有 id / name / qr / payee / hint
pay.methods[].qr 字符串 收款码图片路径，比如 'assets/pay-wechat.png'
pay.methods[].payee 字符串 收款人称呼，填了会显示「转给 XXX」。现在是空的
pay.default 字符串 默认选中哪个支付方式，写某项的 id，现在是 'wechat'
pay.note 字符串 订单页收款码下面的小字
pay.proofMax 数字 付款单号最多几位，默认 40
member.price 数字 会员年费，单位元，现在是 100
member.days 数字 有效期天数，现在是 365
member.perks[] 数组 会员权益。title 加粗、desc 说明
admin.pin 字符串 后台口令，现在是 '2580'

七、数据存在哪

单机模式下，所有数据存在浏览器的 localStorage 里。名字都带前缀 mandao_。

键名存的是什么
mandao_goods_v1所有菜品（含下架的）
mandao_categories_v1分类
mandao_cart_v1购物车
mandao_orders_v1所有订单
mandao_counter_v1取餐号计数器（按天重置）
mandao_member_v1会员状态、到期时间
mandao_session_v1登录的手机号
mandao_admin_v1是否已解锁后台
mandao_pay_method_v1顾客上次选的支付方式
清浏览器缓存 = 数据全没。 包括菜单改动、订单、会员。别用无痕窗口当点单机，关掉就清空。 换设备数据也不会跟过去。

菜单有一个「恢复成初始菜单」的按钮（页面最下面，要二次确认），会把菜品和分类重置回最初的 13 道。订单和会员不受影响。

九、已知限制

限制为什么怎么解
顾客手机下单看不到你改的菜单 没有后端，数据在各自浏览器 接腾讯云开发
付款要顾客手动输金额 个人收款码是静态码，带不了金额 开商家收款码，要营业执照
手机上扫不了自己的屏幕 同一台设备没法拍自己 页面有提示：长按存图再从相册识别
每笔收款要你手动确认 个人收款码没有回调通知 开商户号接支付回调
清缓存数据全丢 存在 localStorage 接云端
收款码公开在网页上 顾客得能看到才能扫 只能给打钱，拿不走东西，风险低
关于合规：会员做成「年费」而不是「储值」，是故意的—— 储值卡属于单用途预付卡，有备案要求；年费不构成预付卡。 如果要改成储值，先说一声，会涉及限额和书面约定的问题。
